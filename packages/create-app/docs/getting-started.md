# Getting Started

`create` is a modern CLI tool for scaffolding webpack-based projects using a template-driven architecture.

Generated projects include:

- Pug templating
- SCSS or Less
- JavaScript or TypeScript
- Production-ready SPA or MPA architecture
- Lightweight reactive runtime via `@razerspine/runtime`
- Production builds powered by `@razerspine/build`
- UI components via `@razerspine/ui`

Projects generated by the CLI are fully standalone and production-ready.

---

## Requirements

- Node.js >= 18
- npm / pnpm / yarn / bun

---

## Create a Project (Interactive Mode)2

```bash
npx @razerspine/create-app my-app
cd my-app
npm run dev
```

### You will be prompted to choose:

- Project type (SPA or MPA)
- Style preprocessor (SCSS or Less)
- Script language (JavaScript or TypeScript)

### The CLI will automatically:

- Validate selected features
- Resolve the correct internal template
- Copy template files
- Patch `package.json`
- Install dependencies (based on detected or selected package manager)
- Prepare a ready-to-run project

---

## Non-Interactive Usage (CI / Automation)

```bash
npx @razerspine/create-app my-app \
--app-type spa \
--style scss \
--script ts \
--pm npm \
--no-install
```

All feature flags must be provided together when running in non-interactive mode.

### Available Flags

| Flag           | Description                  |
|----------------|------------------------------|
| `--app-type`   | `spa \| mpa`                 |
| `--style`      | `scss \| less`               |
| `--script`     | `ts \| js`                   |
| `--pm`         | `npm \| pnpm \| yarm \| bun` |
| `--no-install` | Skip dependency installation |
| `--dry-run`    | Do not write files           |

## Package Manager Support

The CLI supports multiple package managers:

- npm (default)
- pnpm
- yarn
- bun

### Behavior:

- If `--pm` is provided → it is used explicitly
- If not → CLI attempts detection via lock files:
  - `pnpm-lock.yaml`
  - `yarn.lock`
  - `bun.lockb`
  - `package-lock.json`
- Fallback → npm

### Additional behavior:

- `package.json` is automatically patched:
  - `packageManager` field is added (e.g. `"pnpm@latest"`)
  - script prefixes (npm run) are replaced accordingly

### Available Scripts

Generated projects include:

```bash
npm run dev
npm run build
npm run preview
```

| Script    | Description                  |
|-----------|------------------------------|
| `dev`     | Starts webpack-dev-server    |
| `build`   | Creates production build     |
| `preview` | Serves `dist` folder locally |

### Environment Testing Scripts

```bash
npm run test:build:netlify
npm run test:build:vercel
npm run test:build:github
npm run test:build:cloudflare
```

These simulate hosting environments to verify production routing behavior.

## Project Types

### SPA (Single Page Application)

SPA templates use `@razerspine/runtime`.

Key features:

- Application bootstrap (`bootstrapApplication`)
- Dependency Injection container
- Router with guards
- Component lifecycle (`onInit`, `onDestroy`)
- Reactive state (Proxy-based)
- Automatic DOM bindings

#### Example

```ts
bootstrapApplication({
  providers: [
    provideRouter(routes)
  ]
});
```

#### Router

```ts
const routes = [
  {path: '/', component: HomePage},
  {path: '/dashboard', component: DashboardPage}
];
```

#### Lifecycle

```text
Route change
  → destroy previous component
  → create new component
  → mount
  → render
  → bind events
  → applyBindings
  → onInit
```

### MPA (Multi Page Application)

MPA templates use a lightweight reactive layer without router/DI.

Features:

- multi-entry webpack config
- reactive store
- manual lifecycle control

#### Example

```ts
const {state} = createStore(initialState, () => update());
applyBindings(document.body, state);
```

#### Lifecycle

```text
DOMContentLoaded
  → new Page()
  → createStore()
  → update()
```

#### Project Structure

Example:

```text
src/
  app/
  pages/
  shared/
  assets/
  styles/
  types/
```

## Template Resolution

Templates are selected automatically based on:

- `--app-type`
- `--style`
- `--script`

Users never choose templates directly.
