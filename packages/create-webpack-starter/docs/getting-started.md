# Getting Started

`create-webpack-starter` is a CLI tool for scaffolding modern webpack-based projects using a **template-driven
architecture**.

Generated projects include:

- Pug templating
- SCSS or Less
- JavaScript or TypeScript
- Production-ready **SPA or MPA architecture**
- Lightweight reactive runtime via `@razerspine/starter-core-scripts`
- Production builds powered by `@razerspine/webpack-core`

Projects generated by the CLI are **fully standalone and production-ready**.

---

## Requirements

- Node.js >= 20
- npm / pnpm / yarn

---

## Create a Project (Interactive Mode)

```bash
npx create-webpack-starter my-app
cd my-app
npm run dev
```

### You will be prompted to choose:

- Project type (**SPA** or **MPA**)
- Style preprocessor (**SCSS** or **Less**)
- Script language (**JavaScript** or **TypeScript**)

### The CLI will automatically:

- Validate selected features
- Resolve the correct internal template
- Copy template files
- Install dependencies
- Prepare a ready-to-run project

---

## Non-Interactive Usage (CI / Automation)

```bash
npx create-webpack-starter my-app \
  --app-type spa \
  --style scss \
  --script ts \
  --no-install
```

All feature flags must be provided together when running in non-interactive mode.

### Available flags:

| Flag           | Description                  |
|----------------|------------------------------|
| `--app-type`   | `spa` or `mpa`               |
| `--style`      | `scss` or `less`             |
| `--script`     | `ts` or `js`                 |
| `--no-install` | Skip dependency installation |

---

## Available Scripts

### Generated projects include the following scripts:

```bash
npm run dev
npm run build
npm run preview
```

| Script    | Description                  |
|-----------|------------------------------|
| `dev`     | Starts webpack-dev-server    |
| `build`   | Creates production build     |
| `preview` | Serves `dist` folder locally |

### Templates also include environment testing scripts for build verification:

```bash
npm run test:build:netlify
npm run test:build:vercel
npm run test:build:github
npm run test:build:cloudflare
```

These simulate hosting environments to verify production routing behavior.

---

## Automatic Hosting Support

Production builds automatically generate routing configuration for common static hosting platforms.

### Supported environments:

- Netlify
- Vercel
- Cloudflare Pages
- GitHub Pages
- Generic static hosting

### Generated files depend on the detected platform:

| Platform             | Generated File      |
|----------------------|---------------------|
| Netlify / Cloudflare | `_redirects`        |
| Vercel               | `vercel.json`       |
| GitHub Pages         | `404.html` fallback |
| Static hosting       | `404.html` fallback |

Hosting detection is based on environment variables provided by hosting platforms.

No manual configuration is required.

## Project Types

### SPA (Single Page Application)

SPA templates include a **structured application runtime** powered by
`@razerspine/starter-core-scripts`.

Key features:

- Application bootstrap via `bootstrapApplication`
- Dependency Injection container
- Router with guard support
- Component lifecycle (`onInit`, `onDestroy`)
- Reactive Proxy-based state
- Automatic DOM bindings

#### SPA Entry Point

```ts
bootstrapApplication({
  providers: [
    provideRouter(routes)
  ]
});
```

#### Router Example

```ts
const routes: Route[] = [
  { path: '/', component: HomePage },
  { path: '/dashboard', component: DashboardPage }
];
```

#### SPA Lifecycle

```text
Route change
  ↓
destroy previous component
  ↓
new Component(container)
  ↓
mount()
  ↓
render()
  ↓
bind events
  ↓
applyBindings()
  ↓
onInit()
```

#### SPA Project Structure

```text
src/
  app/
    app.ts
    routes.ts
    app.pug
  pages/
    home/
    not-found/
  shared/
    layout/
    mixins/
  assets/
    i18n/
    icons/
    images/
  styles/
    main.scss
  types/
```

Best suited for:

- dashboards
- admin panels
- applications
- client-side routed systems

### MPA (Multi Page Application)

MPA templates use the same reactive engine but without Router or DI container.

Each page is an independent entry point.

Features:

- multi-entry webpack builds
- Proxy-based reactive store
- manual event binding
- explicit lifecycle management

#### MPA Initialization Pattern

```ts
const { state } = createStore(initialState, () => update());
applyBindings(document.body, state);
```

#### MPA Lifecycle

```text
DOMContentLoaded
  ↓
new PageClass()
  ↓
createStore()
  ↓
update()
```

Best suited for:

- marketing websites
- landing pages
- static content-heavy sites
- SEO-driven projects

## How Template Resolution Works

Templates are selected automatically based on three feature flags:

- `--app-type`
- `--style`
- `--script`

The CLI resolves an internal template key.

Users never select templates directly.

---

## Shared Runtime Packages

Generated projects depend on:

- `@razerspine/webpack-core`
- `@razerspine/pug-ui-kit`
- `@razerspine/starter-core-scripts`

These are installed as normal semver dependencies.

## After Project Creation

Typical next steps:

- extend layouts in `src/shared/layout`
- add new pages in `src/pages`
- modify router configuration
- add API services
- configure localization

---

## Standalone Output

Generated projects are **fully independent**:

- no dependency on the CLI
- no hidden runtime
- no framework lock-in
- safe to deploy immediately
