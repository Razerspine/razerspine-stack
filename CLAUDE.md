## Overview

Razerspine Stack is a monorepo (npm workspaces) containing four interdependent packages:

- **`@razerspine/create-app`** (`packages/create-app/`) — CLI that scaffolds SPA/MPA projects from 8 templates
- **`@razerspine/build`** (`packages/build/`) — Webpack 5 configuration abstraction exposing a `defineConfig()` API
- **`@razerspine/runtime`** (`packages/runtime/`) — Lightweight SPA engine with DI container, router, proxy-based reactivity, and a DOM binding system
- **`@razerspine/ui`** (`packages/ui/`) — Design system: Pug mixins, SCSS/Less design tokens, and a CSS build pipeline

Templates generated by the CLI reference **published npm versions** of the other packages, never workspace links.

## Commands

### Root (all packages)
```sh
npm run build           # Build all packages
npm run test:cli        # Test create-app (unit + integration + e2e)
npm run test:runtime    # Test runtime
npm run test:build      # Test build (includes fixture setup)
npm run test:ui         # Test UI (includes fixture setup)
npm run templates:install  # Install dependencies in all templates
npm run templates:clean    # Clean template build artifacts
```

### Per-package test layers
Run from within the package directory (`cd packages/<name>`):
```sh
npx vitest run tests/unit          # Unit tests only
npx vitest run tests/integration   # Integration tests only
npx vitest run tests/e2e           # E2E tests only
npx vitest run tests/snapshots     # Snapshot tests (build, ui)
npx vitest run tests/unit/foo.test.ts  # Single test file
```

### Per-package build
```sh
# create-app & runtime — tsup (dual CJS + ESM output)
npm run build

# build package — tsc (emits .d.ts + CommonJS)
npm run build

# ui — custom pipeline (PostCSS/Sass/Less → CSS, then copy + tsc)
npm run build:css && npm run build:copy && npm run build:ts
```

## Architecture

### `create-app` — CLI scaffolding
Pipeline-based: `src/core/pipeline.ts` orchestrates discrete **steps** (`src/steps/`) that validate input, copy template files, patch `package.json`, install dependencies, and run initial builds. The CLI entry resolves prompts/args via `src/cli/` and calls `createApp()`.

Eight templates live in `packages/create-app/templates/` named by the pattern `{spa|mpa}-{scss|less}-{ts|js}`. They are copied (not symlinked) into generated projects.

### `build` — Webpack abstraction
`defineConfig(options)` in `src/core/create-base-config.ts` returns a resolved webpack `Configuration`. Option resolution flows through `src/options/` (entry normalization, template detection), rules through `src/rules/` (loaders), and plugins through `src/plugins/` (HtmlWebpackPlugin, PugWebpackPlugin, deduplication across MPA pages). A React preset lives in `src/presets/`.

### `runtime` — SPA engine
Multiple entry points (each independently importable):
- `core/` — DI container (`Container`, `Injectable`)
- `router/` — hash/history SPA router
- `reactivity/` — `createStore()`, Proxy-based reactive state
- `view/` — `BaseComponent`, lifecycle hooks, template rendering
- `view/bindings/engine/processors/` — pluggable DOM binding processors (`bind`, `class`, `for`, `model`, `show`)
- `http/` — `ApiService`, `ApiError`
- `platform/` — `ThemeService`, `TranslationService`

### `ui` — Design system
Source in `src/styles/scss/` and `src/styles/less/`. Pug mixins in `src/pug/mixins/`. The build compiles sources with PostCSS/Sass/Less, produces minified CSS, then copies raw sources and type declarations.

## Testing conventions

| Layer | Scope | Environment |
|---|---|---|
| Unit | Isolated functions/classes | Node |
| Integration | Module interactions with mocks | Node (build/create-app), happy-dom (runtime/ui) |
| E2E | Real CLI execution in temp dirs | Node |
| Snapshots | CSS/webpack output | Node |

E2E tests spin up real child processes and write to `os.tmpdir()` with a `create-app-*` prefix; cleanup is handled by global teardown.

The `build` and `ui` packages require fixture setup before snapshot/integration tests — this is why `npm run test:build` and `npm run test:ui` at the root include a pre-step.

## Key constraints

- **Node.js** ≥18 for `create-app`; ≥20 for `build` and `runtime`
- **TypeScript** targets: `ES2019` (build, runtime, ui), `ES2020` (create-app)
- **`@razerspine/runtime`** has zero runtime dependencies by design
- Peer dependencies for webpack plugins are optional and resolved at runtime (not bundled)
- CI runs tests on Node 20, 22, and 24 sequentially: build → runtime → ui → cli
